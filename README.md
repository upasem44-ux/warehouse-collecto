# Warehouse Collecto — دواكم

تطبيق Flutter لتحصيل الموزعين، مع قاعدة محلية للعمل دون اتصال وخادم مركزي اختياري لمشاركة الحسابات والعملاء والسندات بين الأجهزة.

## الحسابات المركزية

- من شاشة الدخول اختر **إعداد اتصال الخادم المركزي** وأدخل عنوان الخادم الخاص بشبكة المحل.
- عند تجهيز الخادم لأول مرة، ينشئ المدير المركزي الأول باستخدام مفتاح التهيئة الذي يضبطه مسؤول الخادم.
- بقية الهواتف تدخل عنوان الخادم نفسه وتسجل الدخول بحسابات أنشأها المدير. لا تنشئ حسابات موزعين جديدة على كل هاتف.
- إدارة المستخدمين وإنشاء الحسابات وإيقافها وتغيير كلمات المرور تتم عبر API المركزي عند وجود جلسة مركزية.
- كلمات مرور الخادم تخزن باستخدام ASP.NET Core PasswordHasher. الخادم يطبق قفل 10 دقائق بعد خمس محاولات فاشلة، وسجل تدقيق، وتحديد معدل الطلبات.
- يحفظ التطبيق رمز الجلسة والملف المختصر للمستخدم في Android secure storage. يسمح بجلسة محلية دون اتصال حتى انتهاء صلاحية الرمز (24 ساعة من تسجيل الدخول). عند انتهاء الصلاحية يلزم اتصال بالخادم لتسجيل الدخول مجدداً.

## العمل دون اتصال والمزامنة

- تبقى قاعدة SQLite المحلية متاحة لإصدار السندات عند انقطاع الشبكة.
- لكل سند معرف عملية عشوائي مستقل لمنع تكرار السند عند إعادة محاولة المزامنة.
- عند فتح لوحة التحكم أثناء وجود اتصال، يحاول التطبيق تنزيل العملاء وإرسال السندات المنتظرة إلى الخادم.
- أول مزامنة للمدير تستورد قائمة العملاء المحلية إلى الخادم فقط إذا كانت قاعدة العملاء المركزية فارغة. بعدها تصبح بيانات العملاء المركزية هي المصدر المشترك للأجهزة.
- السندات المقبولة مركزياً تُعلّم محلياً بأنها مرحّلة. إذا فشل الاتصال تبقى معلقة للمحاولة التالية.

## نشر الخادم

الخادم في `server/WarehouseCollecto.Api` مبني على ASP.NET Core 10. ينشئ GitHub Actions حزمة Windows x64 مستقلة داخل Artifact باسم `warehouse-collecto-windows-server`.

راجع [دليل إعداد الخادم](server/README.md) لتنزيل الحزمة، وتشغيلها على جهاز المحل، وإنشاء المدير الأول، وفتح منفذ LAN الخاص. لا تعرض منفذ HTTP على الإنترنت؛ للوصول من خارج شبكة المحل استخدم VPN أو HTTPS reverse proxy موثوق.

## حدود النسخة الحالية

- وجود API وكود المزامنة لا يعني أن أجهزة المحل متصلة بالفعل؛ يلزم تشغيل الخادم على جهاز دائم التشغيل، وضبط عنوانه في كل هاتف، ثم اختبار عدة أجهزة على الشبكة نفسها.
- المزامنة الحالية تشمل العملاء والسندات فقط. تكامل LiveExPro 8 غير منفذ، ويحتاج مخطط قاعدة البيانات ووسيلة ربط مصرح بها.
- الخادم يستخدم SQLite و `EnsureCreated` في هذه النسخة الأولية؛ يلزم اعتماد EF Core migrations وخطة نسخ احتياطي واستعادة قبل الاستخدام المالي الإنتاجي.
- قاعدة SQLite على الهاتف ليست مشفرة حالياً بـ SQLCipher. Android secure storage يحمي رمز الجلسة، لكنه لا يشفر تلقائياً ملف بيانات SQLite.
- لا يمكن ضمان عدم الاختراق أو الانهيار بنسبة 100%. يجب إجراء اختبار قبول ومراجعة أمنية واستعادة نسخة احتياطية قبل الاعتماد على النظام في عمليات مالية فعلية.

## البناء والاختبارات

تعمل GitHub Actions على اختبارات Flutter، وتحليل Dart، وبناء APK، وبناء API، ونشر خادم Windows ذاتياً.
